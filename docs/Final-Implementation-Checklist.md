## 1️⃣3️⃣ РИСКИ И МИТИГАЦИЯ

### Риск 1: Не хватит времени на все P0-функции

**Вероятность:** Средняя  
**Митигация:**
- Приоритизировать внутри P0 (что критичнее)
- Минимизировать scope словаря/подборок (5 терминов, 3 подборки)
- Отложить мероприятия в P1 (если критично)

### Риск 2: Психолог не успевает валидировать вопросы квизов

**Вероятность:** Низкая  
**Митигация:**
- Начать валидацию параллельно с разработкой
- Если не успевает → запустить без квизов (остальные интерактивы работают)
- Или запустить с 1 квизом (QZ-01, тревога)

### Риск 3: Изменения внешних API (Google/ЮKassa/Telegram)

**Вероятность:** Низкая  
**Митигация:**
- Использовать официальные SDK/библиотеки
- Мониторить changelogs
- Версионировать API-запросы
- ACL защищает от breaking changes

### Риск 4: Проблемы с производительностью

**Вероятность:** Низкая  
**Митигация:**
- Профилирование на staging
- Кэширование (Redis)
- CDN для статики
- Индексы БД по модели данных
- Нагрузочное тестирование перед prod

### Риск 5: Security инцидент

**Вероятность:** Низкая  
**Митигация:**
- Security audit перед запуском
- Все секреты в secret store
- RBAC + audit log
- Шифрование P2
- Регулярные бэкапы
