## Введение

### Цель

Обеспечить доступность сайта для всех пользователей, включая людей с:
- Нарушениями зрения (слепота, слабовидение, дальтонизм)
- Нарушениями слуха
- Моторными нарушениями
- Когнитивными особенностями
- Временными ограничениями (травмы, усталость)

### Стандарт

**WCAG 2.1 Level AA** — минимальный обязательный уровень

**Уровни соответствия:**
- **A**: Базовый (минимум)
- **AA**: Расширенный (наша цель)
- **AAA**: Максимальный (опционально)

## WCAG Принципы

### 1. Perceivable (Воспринимаемость)
Информация и компоненты интерфейса должны быть представлены так, чтобы пользователи могли их воспринять.

### 2. Operable (Управляемость)
Компоненты интерфейса и навигация должны быть управляемыми.

### 3. Understandable (Понятность)
Информация и управление интерфейсом должны быть понятны.

### 4. Robust (Надежность)
Контент должен быть достаточно надежным для интерпретации различными user agents, включая вспомогательные технологии.

## Воспринимаемость (Perceivable)

### 1.1 Текстовые альтернативы

#### 1.1.1 Нетекстовый контент (A)

- [ ] Все изображения имеют `alt` атрибут
- [ ] Декоративные изображения имеют пустой `alt=""` или `aria-hidden="true"`
- [ ] Иконки в кнопках имеют `aria-label` или визуальный текст
- [ ] SVG иконки имеют `<title>` или `aria-label`
- [ ] CAPTCHA имеет альтернативу (audio, другой метод)

```html
<!-- Хорошо -->
<img src="hero.jpg" alt="Психолог беседует с клиентом в уютном офисе">

<!-- Декоративное изображение -->
<img src="pattern.png" alt="" aria-hidden="true">

<!-- Иконка в кнопке -->
<button aria-label="Закрыть">
  <svg aria-hidden="true">...</svg>
</button>

<!-- SVG с title -->
<svg>
  <title>Календарь записи</title>
  <path d="..."/>
</svg>
```

---

### 1.2 Медиа на основе времени

#### 1.2.1 Только аудио и только видео (A)

- [ ] Аудио файлы имеют текстовую транскрипцию
- [ ] Видео без звука имеет аудио дорожку или описание

#### 1.2.2 Субтитры (A)

- [ ] Все видео с аудио имеют субтитры

#### 1.2.3 Аудио описание или альтернатива медиа (A)

- [ ] Видео имеет аудио описание или полную текстовую альтернативу

---

### 1.3 Адаптируемость

#### 1.3.1 Информация и взаимосвязи (A)

- [ ] Используется семантический HTML (`<h1>`, `<nav>`, `<main>`, `<button>`)
- [ ] Заголовки имеют правильную иерархию (H1 → H2 → H3)
- [ ] Формы имеют связанные `<label>` с `for` атрибутом
- [ ] Списки используют `<ul>`, `<ol>`, `<li>`
- [ ] Таблицы имеют `<th>` для заголовков

```html
<!-- Хорошо: семантический HTML -->
<nav aria-label="Основная навигация">
  <ul>
    <li><a href="/services">Услуги</a></li>
  </ul>
</nav>

<main>
  <h1>Главный заголовок</h1>
  <h2>Подзаголовок</h2>
</main>

<!-- Форма с label -->
<label for="email">Email</label>
<input type="email" id="email" name="email">
```

#### 1.3.2 Значимая последовательность (A)

- [ ] Порядок чтения в DOM соответствует визуальному порядку
- [ ] Tab order логичен и предсказуем
- [ ] Flexbox/Grid не нарушают логический порядок

#### 1.3.3 Сенсорные характеристики (A)

- [ ] Инструкции не полагаются только на форму, размер, цвет
- [ ] Используются текстовые метки, не только иконки

```html
<!-- Плохо -->
<p>Нажмите зеленую кнопку справа</p>

<!-- Хорошо -->
<p>Нажмите кнопку "Записаться"</p>
```

#### 1.3.4 Ориентация (AA)

- [ ] Контент не ограничен одной ориентацией (portrait/landscape)
- [ ] Интерфейс адаптируется к любой ориентации

#### 1.3.5 Определение назначения ввода (AA)

- [ ] Поля форм имеют `autocomplete` атрибут
- [ ] Используются подходящие `type` для input (email, tel, url)

```html
<input 
  type="email" 
  id="email" 
  name="email" 
  autocomplete="email"
  aria-label="Адрес электронной почты"
>

<input 
  type="tel" 
  id="phone" 
  name="phone" 
  autocomplete="tel"
>
```

---

### 1.4 Различимость

#### 1.4.1 Использование цвета (A)

- [ ] Цвет не единственный способ передачи информации
- [ ] Ссылки различимы не только по цвету (underline, иконка)
- [ ] Состояния (успех, ошибка) имеют иконки/текст, не только цвет

```html
<!-- Хорошо: иконка + цвет -->
<div class="alert alert--error">
  <svg class="icon-error">...</svg>
  <p>Пожалуйста, заполните все обязательные поля</p>
</div>
```

#### 1.4.2 Управление аудио (A)

- [ ] Автоматически воспроизводимое аудио >3 сек имеет паузу/стоп
- [ ] Фоновая музыка имеет контроль громкости

#### 1.4.3 Контрастность (минимум) (AA)

- [ ] Обычный текст: минимум **4.5:1** контраст с фоном
- [ ] Крупный текст (18px+ или 14px+ bold): минимум **3:1**
- [ ] UI компоненты и графика: минимум **3:1**

**Проверка:**
```
Sage-900 (#1A3330) на white → 12.5:1 ✅
Sage-600 (#3D7369) на white → 5.2:1 ✅
Sand-600 (#87827A) на white → 4.6:1 ✅
```

#### 1.4.4 Изменение размера текста (AA)

- [ ] Текст можно увеличить до 200% без потери функциональности
- [ ] Используются относительные единицы (rem, em, %)
- [ ] Нет горизонтального скролла при zoom 200%

```css
/* Хорошо */
font-size: 1rem; /* 16px */
padding: 1em; /* Относительно font-size */
max-width: 65ch; /* Относительно ширины символа */

/* Плохо */
font-size: 16px; /* Абсолютные пиксели */
width: 1200px; /* Фиксированная ширина */
```

#### 1.4.5 Изображения текста (AA)

- [ ] Используется настоящий текст, а не изображения текста
- [ ] Исключения: логотипы, брендинг

#### 1.4.10 Reflow (AA)

- [ ] Контент адаптируется к ширине 320px без горизонтального скролла
- [ ] Без потери информации или функциональности при zoom 400%

#### 1.4.11 Контрастность не текстового контента (AA)

- [ ] UI компоненты (кнопки, поля ввода) имеют контраст 3:1
- [ ] Границы и иконки имеют контраст 3:1

#### 1.4.12 Интервалы текста (AA)

- [ ] Контент не ломается при пользовательских настройках интервалов:
  - Line height (line spacing): минимум 1.5x font-size
  - Spacing following paragraphs: минимум 2x font-size
  - Letter spacing: минимум 0.12x font-size
  - Word spacing: минимум 0.16x font-size

```css
/* Поддержка пользовательских интервалов */
p {
  line-height: 1.6; /* Минимум 1.5 */
  margin-bottom: 2em; /* Минимум 2x font-size */
}
```

#### 1.4.13 Контент при наведении или фокусе (AA)

- [ ] Тултипы/поповеры можно закрыть Esc без перемещения фокуса
- [ ] Можно навести курсор на сам тултип (не исчезает)
- [ ] Тултип не перекрывает важный контент

## Управляемость (Operable)

### 2.1 Доступность с клавиатуры

#### 2.1.1 Клавиатура (A)

- [ ] Все функции доступны с клавиатуры
- [ ] Tab, Enter, Space, стрелки работают корректно
- [ ] Нет "ловушек" клавиатуры (можно выйти из любого элемента)

**Проверка:** Отключите мышь и пройдите весь сайт только с клавиатуры.

#### 2.1.2 Без ловушки клавиатуры (A)

- [ ] Фокус не застревает в модалках, меню, custom виджетах
- [ ] Можно закрыть модалку по Esc или Tab out

```javascript
// Хорошо: закрытие модалки по Esc
modal.addEventListener('keydown', (e) => {
  if (e.key === 'Escape') {
    closeModal();
  }
});
```

#### 2.1.4 Горячие клавиши (A)

- [ ] Символьные клавиши (shortcuts) можно отключить/переназначить
- [ ] Используются modifier keys (Ctrl, Alt, Cmd)

---

### 2.2 Достаточно времени

#### 2.2.1 Настройка времени (A)

- [ ] Пользователь может отключить/продлить/настроить таймеры
- [ ] Предупреждение перед истечением времени сессии

#### 2.2.2 Пауза, стоп, скрытие (A)

- [ ] Автоматические обновления/анимации можно остановить
- [ ] Движущийся контент можно поставить на паузу

---

### 2.3 Приступы и физические реакции

#### 2.3.1 Три вспышки или ниже порога (A)

- [ ] Нет контента, который мигает более 3 раз в секунду
- [ ] Избегаем быстрых анимаций и стробоскопа

---

### 2.4 Навигация

#### 2.4.1 Обход блоков (A)

- [ ] Есть "Skip to main content" ссылка
- [ ] Повторяющиеся блоки можно пропустить

```html
<!-- Skip link (в начале body) -->
<a href="#main-content" class="skip-link">
  Перейти к основному контенту
</a>

<nav>...</nav>

<main id="main-content">
  <h1>Главный заголовок</h1>
</main>
```

```css
.skip-link {
  position: absolute;
  top: -40px;
  left: 0;
  padding: 8px;
  background: var(--color-sage-700);
  color: white;
  text-decoration: none;
  z-index: 100;
}

.skip-link:focus {
  top: 0;
}
```

#### 2.4.2 Название страницы (A)

- [ ] Все страницы имеют уникальный и описательный `<title>`
- [ ] Формат: "Название страницы | Название сайта"

```html
<title>Услуги — Консультации психолога онлайн | Эмоциональный баланс</title>
```

#### 2.4.3 Порядок фокуса (A)

- [ ] Tab order логичен и соответствует визуальному порядку
- [ ] Не используется `tabindex` > 0 (нарушает естественный порядок)

#### 2.4.4 Назначение ссылки (в контексте) (A)

- [ ] Назначение ссылки понятно из текста ссылки или контекста
- [ ] Избегаем "Читать далее", "Нажмите здесь"

```html
<!-- Плохо -->
<a href="/article">Читать далее</a>

<!-- Хорошо -->
<a href="/article">Читать статью "Как работать с тревогой"</a>

<!-- Хорошо: с aria-label -->
<a href="/article" aria-label="Читать статью 'Как работать с тревогой'">
  Читать далее
</a>
```

#### 2.4.5 Несколько способов (AA)

- [ ] Есть минимум 2 способа найти страницу:
  - Навигация
  - Поиск
  - Карта сайта
  - Breadcrumbs

#### 2.4.6 Заголовки и метки (AA)

- [ ] Заголовки описывают тему или назначение
- [ ] Метки полей форм описывают назначение

#### 2.4.7 Видимый фокус (AA)

- [ ] Все интерактивные элементы имеют видимый focus indicator
- [ ] Контраст focus indicator минимум 3:1

```css
/* Хорошо: видимый focus */
*:focus-visible {
  outline: 3px solid var(--color-sage-500);
  outline-offset: 2px;
}

/* Убираем для mouse users */
*:focus:not(:focus-visible) {
  outline: none;
}
```

---

### 2.5 Модальности ввода

#### 2.5.1 Жесты с указателем (A)

- [ ] Функциональность, использующая мультисенсорные жесты, доступна с одним указателем

#### 2.5.2 Отмена указателя (A)

- [ ] Действие выполняется по `mouseup` (можно отменить, двигая курсор)
- [ ] Не используем только `mousedown` для критичных действий

#### 2.5.3 Метка в имени (A)

- [ ] Видимый текст кнопки/ссылки включен в `aria-label`/`aria-labelledby`

```html
<!-- Хорошо -->
<button aria-label="Записаться на консультацию">
  Записаться
</button>

<!-- Плохо: текст не соответствует aria-label -->
<button aria-label="Забронировать">
  Записаться
</button>
```

#### 2.5.4 Активация движением (A)

- [ ] Функциональность, активируемая движением устройства, имеет UI альтернативу

## Понятность (Understandable)

### 3.1 Читаемость

#### 3.1.1 Язык страницы (A)

- [ ] Атрибут `lang` установлен на `<html>`
- [ ] Части контента на другом языке имеют `lang`

```html
<html lang="ru">
<body>
  <p>Основной текст на русском.</p>
  <p lang="en">Some text in English.</p>
</body>
</html>
```

#### 3.1.2 Язык частей (AA)

- [ ] Цитаты/фразы на другом языке имеют `lang` атрибут

---

### 3.2 Предсказуемость

#### 3.2.1 При фокусе (A)

- [ ] Фокус на элементе не вызывает неожиданных изменений контекста
- [ ] Не открываются модалки/dropdown автоматически при табе

#### 3.2.2 При вводе (A)

- [ ] Ввод данных не вызывает автоматических изменений контекста
- [ ] Форма не отправляется автоматически при заполнении последнего поля

#### 3.2.3 Согласованная навигация (AA)

- [ ] Навигация повторяется в том же порядке на всех страницах
- [ ] Меню не меняет порядок пунктов

#### 3.2.4 Согласованная идентификация (AA)

- [ ] Одинаковые компоненты имеют одинаковые имена/метки
- [ ] Иконка "корзина" везде называется "корзина", не "тележка"

---

### 3.3 Помощь при вводе

#### 3.3.1 Идентификация ошибки (A)

- [ ] Ошибки описаны текстом (не только красным цветом)
- [ ] Понятно, какое поле содержит ошибку

```html
<div class="input-group">
  <label for="email">Email</label>
  <input 
    type="email" 
    id="email" 
    class="input input--error"
    aria-invalid="true"
    aria-describedby="email-error"
  >
  <span class="input-error" id="email-error">
    <svg aria-hidden="true">...</svg>
    Пожалуйста, введите корректный email
  </span>
</div>
```

#### 3.3.2 Метки или инструкции (A)

- [ ] Все поля форм имеют метки (`<label>`)
- [ ] Сложные поля имеют инструкции или примеры

```html
<label for="phone">Телефон</label>
<input 
  type="tel" 
  id="phone"
  placeholder="+7 (999) 123-45-67"
  aria-describedby="phone-hint"
>
<span class="input-hint" id="phone-hint">
  Формат: +7 (XXX) XXX-XX-XX
</span>
```

#### 3.3.3 Предложение по исправлению ошибки (AA)

- [ ] Сообщения об ошибках содержат советы по исправлению
- [ ] Не просто "Неверный формат", а "Используйте формат DD.MM.YYYY"

#### 3.3.4 Предотвращение ошибок (юридические, финансовые, данные) (AA)

- [ ] Критичные действия (удаление, оплата) имеют подтверждение
- [ ] Можно просмотреть и исправить данные перед отправкой

```html
<!-- Модалка подтверждения -->
<div class="modal" role="dialog" aria-labelledby="confirm-title">
  <h2 id="confirm-title">Подтвердите удаление</h2>
  <p>Вы уверены, что хотите удалить запись в дневнике?</p>
  <button class="btn btn-secondary">Отмена</button>
  <button class="btn btn-primary">Удалить</button>
</div>
```

## Надежность (Robust)

### 4.1 Совместимость

#### 4.1.1 Парсинг (A)

- [ ] HTML валиден (нет дублирующихся ID, закрыты теги)
- [ ] Используется валидный HTML5

#### 4.1.2 Имя, роль, значение (A)

- [ ] Custom компоненты имеют подходящие ARIA атрибуты
- [ ] Состояния компонентов доступны программно

**ARIA атрибуты для custom компонентов:**

**Button:**
```html
<div role="button" tabindex="0" aria-pressed="false">
  Toggle
</div>
```

**Checkbox:**
```html
<div role="checkbox" tabindex="0" aria-checked="false">
  Agree to terms
</div>
```

**Tab Panel:**
```html
<div role="tablist">
  <button role="tab" aria-selected="true" aria-controls="panel1">
    Tab 1
  </button>
</div>
<div role="tabpanel" id="panel1">
  Content
</div>
```

**Accordion:**
```html
<div class="accordion">
  <button 
    class="accordion__trigger"
    aria-expanded="false"
    aria-controls="accordion-content-1"
  >
    Question
  </button>
  <div id="accordion-content-1" hidden>
    Answer
  </div>
</div>
```

**Modal:**
```html
<div 
  class="modal" 
  role="dialog" 
  aria-modal="true"
  aria-labelledby="modal-title"
>
  <h2 id="modal-title">Title</h2>
</div>
```

#### 4.1.3 Сообщения о статусе (AA)

- [ ] Динамические обновления объявляются screen reader
- [ ] Используются `role="status"`, `role="alert"`, `aria-live`

```html
<!-- Toast notification -->
<div 
  class="toast" 
  role="status" 
  aria-live="polite"
>
  Запись успешно создана
</div>

<!-- Критичное уведомление -->
<div 
  class="alert alert--error" 
  role="alert"
>
  Ошибка: неверный формат email
</div>
```

## Тестирование

### Автоматическое тестирование

**Инструменты:**
- [axe DevTools](https://www.deque.com/axe/devtools/) (Chrome/Firefox extension)
- [Lighthouse](https://developers.google.com/web/tools/lighthouse) (встроен в Chrome)
- [WAVE](https://wave.webaim.org/) (веб-сервис)
- [Pa11y](https://pa11y.org/) (CLI/CI)

```bash
# Lighthouse CLI
npm install -g lighthouse
lighthouse https://example.com --only-categories=accessibility

# Pa11y
npm install -g pa11y
pa11y https://example.com
```

---

### Ручное тестирование

#### 1. Keyboard Navigation

- [ ] Пройдите весь сайт только с клавиатуры (Tab, Enter, Space, стрелки)
- [ ] Проверьте, что focus indicator видим
- [ ] Проверьте, что можно закрыть модалки по Esc

#### 2. Screen Reader Testing

**Windows:** NVDA (бесплатный)  
**macOS:** VoiceOver (встроен)  
**Mobile:** TalkBack (Android), VoiceOver (iOS)

**Что проверить:**
- [ ] Все тексты озвучиваются
- [ ] Иконки и изображения озвучиваются корректно
- [ ] Навигация по заголовкам работает (H key в NVDA/JAWS)
- [ ] Формы озвучиваются с метками и инструкциями

#### 3. Контрастность

## Чеклисты по компонентам

### Buttons

- [ ] Используется `<button>` или `role="button"`
- [ ] Имеет доступное имя (текст или `aria-label`)
- [ ] `tabindex="0"` для custom кнопок
- [ ] Клавиатурная поддержка (Enter, Space)
- [ ] Видимый focus indicator
- [ ] Disabled состояние: `disabled` или `aria-disabled="true"`

---

### Links

- [ ] Используется `<a href>`
- [ ] Назначение ссылки понятно из текста
- [ ] External links объявлены (`aria-label="Открывается в новой вкладке"`)
- [ ] Видимый focus indicator
- [ ] Не используется `href="#"` для кнопок

---

### Forms

- [ ] Все поля имеют `<label>` с `for` атрибутом
- [ ] Обязательные поля помечены (визуально и `required`)
- [ ] Ошибки озвучиваются (`aria-invalid`, `aria-describedby`)
- [ ] Группы полей используют `<fieldset>` и `<legend>`
- [ ] `autocomplete` атрибуты для персональных данных

---

### Modals

- [ ] `role="dialog"` или `role="alertdialog"`
- [ ] `aria-modal="true"`
- [ ] `aria-labelledby` указывает на заголовок
- [ ] Фокус перемещается в модалку при открытии
- [ ] Можно закрыть по Esc
- [ ] Фокус возвращается после закрытия
- [ ] Фоновый контент недоступен (inert/aria-hidden)

---

### Navigation

- [ ] Используется `<nav>` с `aria-label`
- [ ] Текущая страница помечена `aria-current="page"`
- [ ] Подменю доступно с клавиатуры (стрелки)
- [ ] Mobile меню имеет правильные ARIA атрибуты

---

### Images

- [ ] `alt` атрибут присутствует
- [ ] `alt` описывает содержание/функцию
- [ ] Декоративные: `alt=""` и `aria-hidden="true"`
- [ ] Complex images имеют длинное описание

---

### Tables

- [ ] Используется `<table>` для табличных данных
- [ ] `<th>` для заголовков с `scope`
- [ ] `<caption>` описывает таблицу
- [ ] Сложные таблицы имеют `id`/`headers` связки
